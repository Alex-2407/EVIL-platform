1. INTRODUZIONE E OBIETTIVO DEL PROGETTO
═══════════════════════════════════════════════════════════════════════════════════

EVIL è una piattaforma web completa, moderna e multifunzionale dedicata alla 
cybersecurity, alla formazione etica nell'hacking (ethical hacking) e alla ricerca
di Open Source Intelligence (OSINT). La piattaforma integra molteplici strumenti
professionali in un unico ecosistema coeso, permettendo a professionisti della 
sicurezza informatica, studenti, ricercatori e appassionati di cybersecurity di:

• Condurre scansioni di sicurezza su URL e domini
• Analizzare vulnerabilità e configurazioni SSL/TLS
• Enumerare DNS records e sottodomini
• Raccogliere informazioni pubbliche (OSINT)
• Simulare attacchi web in ambienti controllati
• Imparare l'ethical hacking attraverso lab virtuali interattivi
• Monitorare attacchi in tempo reale su scala mondiale
• Gestire profili utente con sistema di progressi e achievement

━━━━━━━━━━━━━━━━━━━━━━━━━━━━

POST /api/auth/register
  Descrizione: Registrazione nuovo utente
  Body: { email, password, name }
  Risposta: { success, message, user, token }
  Validazione: Email unica, password minimale 8 caratteri

POST /api/auth/login
  Descrizione: Accesso utente
  Body: { email, password }
  Risposta: { success, message, user, token }
  Token: JWT base64 (localStorage)

POST /api/auth/logout
  Descrizione: Logout sicuro
  Headers: Authorization: Bearer [token]
  Effetto: Invalidazione token server-side

GET /api/auth/profile
  Descrizione: Recupero profilo autenticato
  Headers: Authorization: Bearer [token]
  Risposta: { user, stats, achievements }

POST /api/auth/verify
  Descrizione: Verifica validità token
  Headers: Authorization: Bearer [token]
  Risposta: { valid, user }


4.2 ENDPOINT STRUMENTI SCANNING
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

POST /api/scan
  Descrizione: Scansione completa URL/dominio
  Body: { url }
  Ritorna:
    • IP resolution (DNS lookup)
    • ASN ownership (Autonomous System Number)
    • SSL/TLS certificate analysis
    • HTTP headers inspection
    • Redirect chain tracing
    • Threat database lookup
  Timeout: 30 secondi

POST /api/dns-enum
  Descrizione: Enumerazione DNS avanzata
  Body: { domain }
  Record: A, AAAA, MX, NS, SOA, TXT, CNAME
  Simulate: Cerca anche record storici/alternativi

POST /api/subdomain-finder
  Descrizione: Scoperta sottodomini
  Body: { domain }
  Metodo: Dizionario + brute force comune
  Risultati: Sottodomini attivi con IP e service

POST /api/ssl-analyzer
  Descrizione: Analisi certificati SSL/TLS
  Body: { domain }
  Ritorna:
    • Subject (CN, O, C)
    • Issuer dettagli
    • Validity dates
    • Algorithm strength
    • Validity chains
  TLS Version: 1.2+

POST /api/vulnerability-scan
  Descrizione: Scansione vulnerabilità
  Body: { url }
  Controlla:
    • CVE pubblici (da NIST, CISA)
    • Weak SSL/TLS versions
    • Missing security headers
    • Outdated frameworks/libraries
    • Common misconfigurations
  Database: NIST NVD, CISA KEV

GET /api/realtime-incidents
  Descrizione: Stream attacchi in tempo reale
  Formato: JSON Array
  Dati:
    • Timestamp di attacco
    • Paese origin/target
    • Tipo attacco (malware, ddos, exploit)
    • Target type (Government, Healthcare, etc)
    • Severity score

5.1 SISTEMA DI AUTENTICAZIONE
━━━━━━━━━━━━━━━━━━━━━━━━━━━

Implementazione:
  • JWT-style Token authentication
  • Password hashing (base) - per produzione: bcrypt
  • Session persistence via localStorage
  • Token expiration logic
  • Logout invalidation

Flusso Login:
  1. Utente inserisce email e password
  2. Frontend valida format email
  3. Fetch POST /api/auth/login
  4. Backend verifica credenziali (file users.json)
  5. Generazione token
  6. localStorage salva: auth_token, user
  7. Redirect a home.html
  8. Header si aggiorna dinamicamente

Flusso Logout:
  1. Click pulsante "Log Out"
  2. Fetch POST /api/auth/logout
  3. localStorage.removeItem(['auth_token', 'user'])
  4. Redirect a login.html
  5. Auth-manager rileva logout
  6. Interfaccia si ripristina

5.3 SISTEMA SCANSIONE COMPLETA URL
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

POST /api/scan analizza:

1. RISOLUZIONE DNS
   • Converte dominio → IP indirizzo
   • Gestisce errori DNS timeout
   • Supporta IPv4 + IPv6

2. IDENTIFICAZIONE ASN
   • Determina Autonomous System Number
   • Database custom ASN (Cloudflare, Amazon, Google, ecc)
   • Mappa a paese e tipo servizio

3. ESTRAZIONE CERTIFICATO SSL/TLS
   • Connessione TLS porta 443
   • Lettura peer certificate
   • Estrae: Subject, Issuer, ValidFrom, ValidTo
   • Analizza catena certificati
   • Rileva scadenza imminente

4. ANALISI HEADER HTTP
   • Fetch di HTTP/HTTPS headers
   • Identifica server software (Apache, Nginx, IIS)
   • Rileva presence di security headers:
     - Content-Security-Policy
     - X-Frame-Options
     - Strict-Transport-Security
     - X-Content-Type-Options

5. TRACCIAMENTO REDIRECT
   • Segue chain 301/302/307/308 redirects
   • Mappa conversione URL
   • Rileva redirect loop
   • Valuta rischi reputazionali

6. LOOKUP THREAT DATABASE
   • Confronta contro database interno
   • Verifica se dominio è noto phishing/malware
   • Calcola risk score (0-100)
   • Genera threat profile


5.4 ENUMERAZIONE DNS AVANZATA
━━━━━━━━━━━━━━━━━━━━━━━━━━━

Query supportate:
  • A records (IPv4)
  • AAAA records (IPv6)
  • MX records (Mail servers)
  • NS records (Name servers)
  • SOA records (Authority)
  • TXT records (Text data, SPF, DKIM)
  • CNAME records (Aliases)
  • SRV records (Service)

Permette:
  • Identificare infrastruktur mail
  • Scoprire name servers
  • Validare SPF/DKIM/DMARC
  • Trovare wildcard records


5.5 SCOPERTA SOTTODOMINI
━━━━━━━━━━━━━━━━━━━━━━━

Metodo:
  • Brute force comune (www, mail, ftp, api, admin, etc)
  • Dictionary-based (1000+ sottodomini comuni)
  • Timeout handling per non-existent
  • Parallel request processing

Output:
  • Sottodomini attivi
  • Relativi indirizzi IP
  • Servizi identificati


5.6 ANALISI VULNERABILITÀ
━━━━━━━━━━━━━━━━━━━━━━━

Verifica:
  • CVE pubblici (integrazione NIST + CISA)
  • SSL/TLS version weakness
  • Missing security headers
  • Server software EOL (End of Life)
  • Known exploits database

Severità:
  • Critical - Exploit remoto immediato
  • High - Compromise probabile
  • Medium - Sfruttamento condizionato
  • Low - Basso impatto pratico


5.7 ANALIZZATORE CERTIFICATI SSL/TLS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Estrae:
  • Subject Distinguished Name (CN, O, OU, C, ST)
  • Issuer (CA Authority)
  • Serial number
  • Public key algorithm (RSA, ECDSA)
  • Signature algorithm
  • Validity period (notBefore, notAfter)
  • Alternative names (SAN)
  • Key size e strength assessment
  • Extended validation status

Avvertenze:
  • Scadenza prossima/prossima
  • Self-signed certificates
  • Mismatched domain
  • Weak crypto algorithms
