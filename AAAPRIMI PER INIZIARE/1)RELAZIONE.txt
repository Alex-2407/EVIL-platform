1. INTRODUZIONE E VISIONE DEL PROGETTO
═══════════════════════════════════════════════════════════════════════════════════

EVIL (Educational Vulnerability & Intelligence Lab) non è un singolo strumento
isolato, ma una SUITE SOFTWARE integrata sviluppata come piattaforma web completa
per la cybersecurity didattica. L'obiettivo è colmare il divario tra teoria
accademica e pratica operativa: l'utente impara, misura i progressi e utilizza
strumenti reali nello stesso ambiente, senza installare software locale.

SITO IN PRODUZIONE:  https://www.projectevil.it
CODICE SORGENTE:    https://github.com/Alex-2407/EVIL-platform
                     (repository PUBBLICO — clonabile, portfolio e deploy cloud)

PROBLEMA AFFRONTATO:
  Le risorse cybersecurity online sono frammentate (scanner separati, corsi
  separati, mappe threat intel altrove). EVIL unifica tutto con identità visiva
  coerente, autenticazione centralizzata e tracciamento del percorso formativo.

SOLUZIONE PROPOSTA:
  Otto sottosistemi brandizzati (EVIL Core, Shield, Forge, Scout, Intel Map,
  Academy, Archive, Vault) più il layer EVIL Chrome per l'interfaccia, che
  insieme costituiscono la piattaforma proprietaria EVIL Suite.

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  Una suite software è un insieme di moduli cooperanti sotto un unico brand.
  In EVIL ogni modulo ha:
    • Responsabilità ben definita (single responsibility)
    • API o script dedicati
    • Pagine HTML associate
    • Integrazione con EVIL Core (auth, log, rate limit)

  Questo approccio è ciò che permette di presentare il lavoro come SVILUPPO
  SOFTWARE ORIGINALE e non come semplice raccolta di link esterni.

4. EVIL CORE — MOTORE CENTRALE DELLA PIATTAFORMA
═══════════════════════════════════════════════════════════════════════════════════

4.1 COS'È EVIL CORE
━━━━━━━━━━━━━━━━━━━

  EVIL Core è il nucleo runtime della suite: senza Core nessun altro modulo
  può funzionare in produzione. Gestisce il ciclo di vita delle richieste HTTP,
  il routing verso i sottosistemi, la persistenza utenti e l'integrazione
  con servizi esterni.

4.2 COMPONENTI SOFTWARE
━━━━━━━━━━━━━━━━━━━━━━━

  File principale:     js/server.js (~2300 righe)
  Servizi dedicati:
    • services/email-service.js      — verifica email, reset password
    • services/token-manager.js      — refresh token (Redis opzionale)
    • services/incidents-service.js  — feed EVIL Intel Map
    • services/virtual-lab-service.js — sessioni EVIL Academy

  Utility:
    • utils/token-utils.js           — cookie httpOnly access/refresh

  Script operativi:
    • js/check-deployment.js         — checklist pre-deploy
    • js/verify-services.js          — test 8 servizi critici
    • scripts/setup-local.js         — setup .env locale
    • scripts/build-home-css.js      — bundle CSS home

4.3 FUNZIONALITÀ CORE
━━━━━━━━━━━━━━━━━━━━━

  • Routing pagine HTML con iniezione asset (header, tema, scrollbar)
  • Servizio file statici (/css, /js, /html, /public, /assets)
  • Compressione gzip, CORS, cookie-parser
  • Health check: GET /health e GET /api/health
  • Trust proxy per deploy dietro Render/nginx
  • Validazione ambiente produzione (JWT forti obbligatori)
  • Audit log e logger strutturato (middleware/logger.js)
  • Sincronizzazione achievements.json → html/achievements.json

4.4 AVVIO E DEPLOY
━━━━━━━━━━━━━━━━━━

  Sviluppo:  npm start  →  build home CSS  →  http://localhost:5000
  Cloud:     Procfile → web: npm start
  Engine:    Node.js 18.x (package.json engines)

5. EVIL SHIELD — LIVELLO DI SICUREZZA INTEGRATO
═══════════════════════════════════════════════════════════════════════════════════

5.1 COS'È EVIL SHIELD
━━━━━━━━━━━━━━━━━━━━

  EVIL Shield non è un prodotto separato installabile: è il LAYER DI SICUREZZA
  trasversale che protegge ogni richiesta API e l'avvio in produzione. È parte
  dell'innovazione architetturale della suite (security-by-design).

5.2 MODULI SHIELD
━━━━━━━━━━━━━━━━━

  middleware/auth.js
    • authenticateToken — JWT da cookie httpOnly
    • authenticateTools — login obbligatorio per strumenti (default)
    • toolsArePublic() — disattivato salvo EVIL_TOOLS_PUBLIC=1 (solo test)
    • Validazione password: 12+ caratteri, maiuscola, numero, speciale
    • Guest user solo in modalità test esplicita

  middleware/sanitization.js
    • sanitizeUrl, sanitizeString, sanitizeEmail
    • assertSafePublicUrl — anti-SSRF (blocco IP privati, localhost, metadata)

  middleware/limiter.js
    • globalLimiter — API (escluse pagine statiche)
    • authLimiter, registerLimiter, passwordResetLimiter, refreshTokenLimiter
    • scanLimiter, dnsLimiter, uploadLimiter, virtualLabLimiter

  middleware/security-headers.js + helmet
  middleware/validation-schemas.js + express-validator
  middleware/upload.js, file-scanner-upload.js

5.3 POLITICA ACCESSO STRUMENTI
━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  REGOLA PRODUZIONE: per usare EVIL Forge e EVIL Scout l'utente DEVE

    • Frontend: tools-api.js, security-check.js → redirect login.html
    • Backend: authenticateTools su POST /api/scan, /api/dns-enum, ecc.

6.3 URL SECURITY CHECK — PIPELINE TECNICA
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  Input URL → sanitizeUrl → assertSafePublicUrl (Shield) → runUrlScan:
    1. Risoluzione DNS / GeoIP
    2. Tracciamento catena redirect
    3. Handshake TLS e analisi certificato
    4. Audit header HTTP (CSP, HSTS, X-Frame-Options, ecc.)
    5. Discovery robots.txt / security.txt
    6. Calcolo security_score e grade
  Timeout operazione: ~45s con gestione 408

6.4 INNOVAZIONE FORGE
━━━━━━━━━━━━━━━━━━━━━

  Integrazione end-to-end in un'unica UI (security-check.html) invece di
  tool separati; un solo login; storico progressi collegato a EVIL Vault.

━━━━━━━━━━━━━━━━━━━━━━━
