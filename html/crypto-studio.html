Obiettivi di apprendimento

  • Distinguere hash, MAC, cifratura simmetrica e asimmetrica, e sapere quale problema risolve ciascuno.

Il laboratorio usa la Web Crypto API del browser: nulla di ciò che scrivi lascia il tuo computer. Per l'uso responsabile degli strumenti di analisi vedi Etica e legge.

Protocollo

TLS 1.3 in un solo round-trip

Il client invia già nel ClientHello la sua parte dello scambio chiavi (key_share); il server risponde con la propria, e da lì in poi tutto è cifrato: certificato, firma dell'handshake (CertificateVerify) e Finished. Bastano un round-trip e chiavi effimere, quindi c'è forward secrecy.

Sicurezza pratica

Quale strumento per quale problema

Una guida rapida alle scelte: i dettagli storici e tecnici sono nelle schede del catalogo.

Usa

  • Password degli utenti → Argon2id (in alternativa bcrypt)
  • Integrità di file e dati → SHA-256, SHA-512 o SHA-3
  • Token API e cookie firmati → HMAC-SHA256 o Ed25519
  • Dati in transito → TLS 1.3 (o 1.2 ben configurato) con certificato valido
  • File e record cifrati → AES-GCM o ChaCha20-Poly1305 (dischi interi: AES-XTS)
  • Scambio di chiavi → X25519 / ECDHE + HKDF; ibrido X25519MLKEM768 dove disponibile
  • Firme digitali → Ed25519, ECDSA P-256 o RSA ≥ 3072 bit (PSS); pianificare il passaggio a ML-DSA

Evita

  • MD5 / SHA-1 per password, firme o integrità critica
  • SHA-256 da solo per le password (troppo veloce)
  • DES, 3DES, RC4: ritirati ovunque
  • AES-CBC senza MAC (padding oracle), AES in modalità ECB
  • Trasporto di chiavi RSA: niente forward secrecy
  • SSL, TLS 1.0 e 1.1 e cipher suite obsolete
  • Nonce/IV riutilizzati in qualsiasi AEAD
