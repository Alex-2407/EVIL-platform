# Lingue e traduzioni

EVIL è scritto in **italiano** (lingua sorgente). La versione **inglese** sta sotto `/en/`
(`/en/`, `/en/quiz-hub.html`…) e si ottiene dalle stesse pagine, sostituendo i testi con le
traduzioni dei dizionari in `i18n/en/`. Per aggiungere una lingua basta aggiungerla a `LANGS`
in `server/site-map.js` e creare `i18n/<lingua>/` con gli stessi file.

## Cosa si traduce e dove

| Cosa | Dove sta il testo italiano | Dove va la traduzione |
|------|----------------------------|-----------------------|
| Testi delle pagine (titoli, paragrafi, pulsanti, `title`, `alt`, `placeholder`, `aria-label`, meta description) | `html/<pagina>.html` | `i18n/en/pages/<pagina>.json` |
| Menu, footer, nomi e descrizioni delle pagine | `server/site-map.js`, `server/chrome.js` | stesso file (campo `en`) |
| Testi creati dal JavaScript | `js/<file>.js`, dentro `t('…')` | `i18n/en/js/<file>.json` |
| File di dati (quiz, catalogo malware, scenari…) | `js/<dati>.js` | `js/i18n/en/<dati>.js` (copia completa tradotta, stesse variabili globali) |
| Messaggi delle API, email | `server/`, `services/`, `middleware/`, dentro `t(lang, '…')` o `req.t('…')` | `i18n/en/server/<percorso>.json` |

## Pagine HTML

Il server divide ogni pagina in **blocchi**: un blocco è un elemento che contiene testo e solo
elementi in linea (`a`, `strong`, `em`, `code`, `span`, `br`, `img`…). La chiave del dizionario è
l'innerHTML del blocco con gli spazi compressi; la traduzione è HTML con **gli stessi tag e gli
stessi attributi** (link, classi), cambia solo il testo (e i `title`/`alt` interni, tradotti).

```json
{
  "Non hai un account? <a href=\"/account.html\">Registrati qui</a>": "No account yet? <a href=\"/account.html\">Sign up here</a>"
}
```

- I link interni restano `/pagina.html`: nella versione inglese diventano `/en/pagina.html` da soli.
- Un blocco da non tradurre (codice, nomi propri, payload d'esempio): `translate="no"` sull'elemento.
- `<pre>`, `<script>`, `<style>`, `<svg>`, `<textarea>` non si traducono mai.
- Header e footer non stanno nelle pagine: al loro posto ci sono `<!--evil:header-->` e
  `<!--evil:footer-->`, riempiti dal server nella lingua giusta.

Flusso:

```bash
node scripts/i18n.js extract quiz-hub.html   # aggiunge le chiavi nuove con valore ""
# compila i valori in i18n/en/pages/quiz-hub.json
node scripts/i18n.js check                   # cosa manca
```

Se cambi un testo italiano, la vecchia traduzione sparisce al prossimo `extract`: ritraducila.

## JavaScript

`js/i18n.js` è caricato in testa a ogni pagina e definisce `window.EVIL_I18N`:

```js
const { t, url, fmtNumber, fmtDate, lang, locale } = window.EVIL_I18N;

el.textContent = t('Nessun risultato');
el.textContent = t('Trovati {n} risultati per {q}', { n: list.length, q: query });
location.href = url('/login.html');                    // → /en/login.html in inglese
date.textContent = fmtDate(iso);                        // it-IT o en-GB
```

Regole:
- il primo argomento di `t()` è **sempre una stringa letterale** (apici singoli, doppi o backtick
  senza `${}`): lo script di estrazione la trova da solo. Le parti variabili vanno nei `{segnaposto}`;
- niente concatenazioni di pezzi di frase (`t('Trovati') + n + t('risultati')`): una frase intera
  con segnaposto, perché l'ordine delle parole cambia tra le lingue;
- plurali: `n === 1 ? t('{n} risultato', { n }) : t('{n} risultati', { n })`;
- link a pagine del sito generati dal JS: sempre con `url()`;
- numeri e date: `fmtNumber()` / `fmtDate()` invece di `toLocaleString('it-IT')`.

```bash
node scripts/i18n.js extract-js quiz-hub.js   # crea/aggiorna i18n/en/js/quiz-hub.json
node scripts/i18n.js build                    # rigenera js/i18n/en.js (lo fa anche l'avvio del server)
```

## File di dati

Per i file grandi di contenuti (`quiz-hub-data.js`, `malware-db-data.js`, `crypto-algorithms-data.js`…)
la versione inglese è una copia completa in `js/i18n/en/` con la **stessa struttura e le stesse
variabili globali**. Il server, sulle pagine `/en/`, carica la copia inglese al posto
dell'originale. Si traducono i testi, non gli identificativi (`id`, chiavi, `correct`, valori usati
dal codice come `severity: "critical"`).

## Server

```js
// in una route
res.status(400).json({ error: req.t('Email non valida') });
// fuori da una richiesta
const { t } = require('../server/i18n');
t(lang, 'Il link scade tra {h} ore', { h: 24 });
```

La lingua di una richiesta API arriva dall'header `X-EVIL-Lang`, poi dal cookie `evil_lang`
(che `js/i18n.js` imposta a ogni pagina), poi dalla pagina di provenienza. `node scripts/i18n.js
extract-server` raccoglie le stringhe in `i18n/en/server/`.

## SEO

- Ogni pagina dichiara `<link rel="alternate" hreflang="it|en|x-default">` e un canonical nella sua lingua.
- `sitemap.xml` elenca tutte le versioni con i link `xhtml:link` alternativi.
- `<html lang>`, `og:locale` e l'header `Content-Language` seguono la lingua.
- Nessun redirect automatico in base alla lingua del browser (i motori di ricerca non hanno
  preferenze): chi non ha l'italiano tra le lingue del browser vede un suggerimento in basso.
